## Purpose and ownership
Motion explains transitions from identity to agents, context and infrastructure; case studies provide evidence. Avoid spectacle that competes with reading.
- GSAP: future section/scroll choreography.
- CSS: Phase 01 interface feedback and field entrance.
- Framer Motion / Motion: future interface feedback when state/gesture complexity warrants it.

Never have multiple animation systems own the same property on the same element. Clean up timelines, listeners, render loops and GPU resources on unmount.

## Proposed motion vocabulary
UI feedback: 120–200ms. Small reveals: 300–500ms. Hero introduction: 600–900ms, without delaying access to text or controls. These are prototype starting points, not approved choreography. Favor transform/opacity and restrained easing. Avoid long staggers and scroll hijacking.

## Future hero behavior — Phase 02 onward
1. Render usable HTML and a verified static portrait first; reserve portrait space to prevent layout shifts.
2. Load WebGL lazily when appropriate. Keep the fallback visible until the scene is ready.
3. Reveal holographic material subtly; preserve recognizable identity and readable text.
4. Proposed fine-pointer interaction: small bounded lighting/parallax response. Touch does not require hover or device orientation.
5. Pause rendering while offscreen or the document is hidden. Bound pixel density, particles and post-processing according to measured device capability.
6. Handle load failure, unsupported WebGL and context loss by restoring the static portrait without hiding page content.

## Reduced motion
Respect prefers-reduced-motion on first render and changes during the session. Disable continuous parallax, scroll scrubbing, camera travel and particle drift. Present a static verified portrait, immediate content and simple state changes. No essential information may exist only in animation. Provide a pause option if continuous decorative motion is retained in the final experience.

## Performance validation
Target 60fps on documented representative hardware; measure frame time during actual interaction. Lower scene complexity or use the static mode when needed. Profile CPU/GPU work, memory, asset loading and scene cleanup. Do not treat the target as a guarantee across devices. No flashing or rapid scan effects.

## Original Phase 01 motion implementation — historical, removed
- CSS owns 180ms control transitions and an 800ms one-time field entrance with `cubic-bezier(.22, 1, .36, 1)` easing. Main content is immediately visible; no loader, scroll hijacking or entrance delay.
- Fine pointers can offset the decorative field by at most 12px horizontally and 8px vertically. Event-driven requestAnimationFrame batches style writes; React does not rerender per pointer movement. There is no idle/continuous rendering loop.
- The field resets on pointer leave, visibility changes and motion/input preference changes. Listeners and pending frame are removed on unmount.
- Reduced motion disables entrance, pointer offset, smooth scrolling and animated UI transitions, including changes during the session. Touch uses the static composition.
- With JavaScript disabled, the server-rendered CSS field, text and anchor navigation remain useful. There is no WebGL dependency or context to fail in Phase 01.
- Future connected transformation direction: likeness → agent graph → retrieval/context → infrastructure → case-study systems → identity. These are concepts, not implemented sequences.
